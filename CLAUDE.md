# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Overview

FlowSync is a training project (LIDR AI4Devs master, module 1: "harness" exercise). The root `README.md` is the generated exercise statement (in Spanish) and `prompts.md` is the template for logging prompts; neither is application code. Two independent npm projects, no root `package.json`:

- `backend/`: AdonisJS 7 API (TypeScript, Lucid ORM, SQLite via better-sqlite3, VineJS validation, access-token auth). **Already complete; do not modify it unless a task explicitly says so.**
- `frontend/`: React 19 + Vite 8 + TypeScript, still the bare Vite template (`src/App.tsx`). This is where feature work happens. The ticket plans to use shadcn/ui components (copied into the repo, not a dependency).

Requires **Node.js 24+** (Node 20 fails with `Unknown file extension ".ts"`).

## Commands

Backend (`cd backend`):
- First-time setup: `npm install && cp .env.example .env && node ace generate:key && node ace migration:run`
- Dev server (HMR, http://localhost:3333): `npm run dev`
- Tests: `npm test` (Japa; suites `unit` and `functional` under `tests/`). Single file: `node ace test --files tests/functional/foo.spec.ts`; by suite: `node ace test functional`. No spec files exist yet, only `tests/bootstrap.ts`.
- `npm run lint`, `npm run typecheck`, `npm run format`
- New migration: `node ace make:migration <name>` (never edit tables by hand)

Frontend (`cd frontend`), run in a separate terminal from the backend:
- `npm install`, `npm run dev` (http://localhost:5173), `npm run build` (`tsc -b && vite build`), `npm run lint` (oxlint)
- No test runner or formatter is configured.

## Backend architecture

Standard AdonisJS layering: `start/routes.ts` → controller → VineJS validator (`app/validators/user.ts`) → Lucid model → `UserTransformer` (controls the exact response shape; never return models directly, use `serialize(...)`).

- Imports use `package.json` `imports` aliases (`#controllers/*`, `#models/*`, `#validators/*`, `#transformers/*`, `#start/*`, ...), not relative paths. Controllers are referenced in routes through the generated `#generated/controllers`.
- `.adonisjs/` and `database/schema.ts` are generated (tuyau registry, routes types, schema from migrations); they are regenerated by the dev server / `node ace migration:run`. Don't hand-edit them.
- All routes are under `/api/v1`:
  - `POST auth/signup`, `POST auth/login`: public. Both return `{ user, token }` (token is an `oat_...` opaque access token).
  - `GET account/profile`, `POST account/logout`: behind `auth` middleware, expect `Authorization: Bearer <token>`.
- Validator details a ticket won't tell you (read `app/validators/user.ts` for the source of truth): signup requires `fullName` (nullable), `email` (unique), `password` (8–32 chars) **and `passwordConfirmation`** (must equal `password`); login takes `email` and `password`. Validation failures come back as 422 with per-field errors; bad credentials on login are an error response too, so the UI must surface both.
- CORS: in dev all origins are allowed (`config/cors.ts`), so the frontend can call `http://localhost:3333` directly.

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project context

FlowSync is the practice project for a course exercise (`README.md` is a generated lesson, not project docs; don't edit it by hand). It is two independent npm packages with no root `package.json`: run commands from inside `backend/` or `frontend/`. Requires Node.js 24+ (older versions fail with `Unknown file extension ".ts"`).

**The backend already exists and is not modified for the exercise; frontend work reads it as the source of truth.** The ticket does not spell out everything the API demands, so check `backend/app/validators/user.ts` rather than guessing.

## Commands

Backend (`backend/`, AdonisJS 7, serves on http://localhost:3333):

```bash
npm install && cp .env.example .env && node ace generate:key && node ace migration:run   # first-time setup
npm run dev          # node ace serve --hmr
npm run typecheck
npm run lint         # eslint
npm run format       # prettier
npm test             # node ace test
node ace test functional                 # one suite (unit | functional)
node ace test --files=tests/functional/foo.spec.ts   # one file
node ace test --tests="test title"       # one test
```

Test suites are configured in `adonisrc.ts` (`tests/unit/**`, `tests/functional/**`), but no spec files exist yet. `npm run lint` currently reports one prettier error, in the generated `database/schema.ts`.

Frontend (`frontend/`, React 19 + Vite, serves on http://localhost:5173):

```bash
npm install
npm run dev
npm run build        # tsc -b && vite build; this is also the typecheck
npm run lint         # oxlint
```

The frontend has no test runner. Prettier is configured in `frontend/.prettierrc.json`, and a `PostToolUse` hook in `.claude/settings.json` runs it on every file the agent writes or edits under `frontend/src/`.

## Backend architecture

Request flow: `start/routes.ts` → `start/kernel.ts` middleware → controller → VineJS validator → Lucid model → transformer → `ctx.serialize()`.

- **Imports** use the `#` subpath aliases from `package.json` (`#models/*`, `#validators/*`, ...), written with `.js` targets mapped to the `.ts` sources.
- **Routes reference generated controllers** (`controllers.NewAccount` from `#generated/controllers`). `.adonisjs/` is generated and committed; it is regenerated by the init hooks in `adonisrc.ts` (`indexEntities`, `generateRegistry`), which run on `node ace` commands. Don't edit it by hand.
- **Models extend generated schema classes.** `database/schema.ts` is generated by `node ace migration:run`; `app/models/user.ts` extends `UserSchema` from it. To change a table, add a new migration; never edit `schema.ts` or an applied migration. Custom column rules go in `database/schema_rules.ts`.
- **Responses** go through `ctx.serialize()` (`providers/api_provider.ts`), which wraps payloads in `{ data: ... }`. Transformers (`app/transformers/`) choose the exposed fields, so a new response field must be added there too.
- **Every response is JSON**: `force_json_response_middleware` forces the `Accept` header.
- **Auth** defaults to the `api` token guard (DB-backed access tokens with the `oat_` prefix). The session guard `web` exists in config but no route uses it. `middleware.auth()` protects the `account` group.
- **Database** is SQLite at `backend/tmp/db.sqlite3` (gitignored). `SESSION_DRIVER` is `memory` under `.env.test`.

## API contract

All routes are under `/api/v1`. Send the token as `Authorization: Bearer <token>`.

| Route | Auth | Body | Success |
| --- | --- | --- | --- |
| `POST /auth/signup` | no | `fullName`, `email`, `password`, `passwordConfirmation` | `{ data: { user, token } }` |
| `POST /auth/login` | no | `email`, `password` | `{ data: { user, token } }` |
| `GET /account/profile` | yes | | `{ data: user }` |
| `POST /account/logout` | yes | | `{ message }` (not wrapped) |

Requirements that are easy to miss on signup:

- `fullName` is **required but nullable**: the key must be present, so a form with only email and password must send `fullName: null`.
- `passwordConfirmation` is required and must equal `password`.
- `password` is 8 to 32 characters; `email` is at most 254 and must be unique.
- Signup returns a token, so a new user is already authenticated.

Errors share one envelope, but differ in detail:

| Case | Status | Body |
| --- | --- | --- |
| Validation failure, including duplicate email on signup | 422 | `{ errors: [{ message, rule, field }] }`, with one entry per failing field |
| Invalid credentials on login | 400 | `{ errors: [{ message: "Invalid user credentials" }] }`, with no `field` |
| Missing or invalid token | 401 | `{ errors: [{ message: "Unauthorized access" }] }` |

Messages are VineJS/Adonis defaults in English, and are not tailored for end users.

CORS allows any origin only when `app.inDev` is true; production has an empty allowlist. The app reads no `CORS_ORIGIN` env var, despite the comment in `.env.example`.

## Frontend architecture

`frontend/src` is still the untouched Vite template (`App.tsx` is the demo page). There is no router, API client, auth state, or Tailwind yet, and shadcn/ui is not set up, although the ticket requires it. shadcn/ui components are copied into the repo and edited freely rather than installed as a dependency. There is no Vite proxy, so the frontend calls the backend at `http://localhost:3333` directly.

TypeScript runs with `verbatimModuleSyntax` and `erasableSyntaxOnly`: use `import type` for types, and avoid enums and parameter properties. `noUnusedLocals` and `noUnusedParameters` are on, so unused code fails `npm run build`.

# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Repository overview

FlowSync is a course project (LIDR AI4Devs). The repo holds two independent npm packages and has no root `package.json`, so run every command from inside `backend/` or `frontend/`.

- `backend/`: an AdonisJS 7 API in TypeScript (Lucid ORM on SQLite, VineJS validation, access-token auth). It is already implemented. In the current exercise (branch `s1/start`) it is **read-only**: treat it as the API contract and do frontend work against it.
- `frontend/`: React 19 + Vite 8 + TypeScript. It is still the bare Vite template, and this is where the work happens. The course calls for **shadcn/ui** components, but shadcn/ui isn't set up yet: there's no Tailwind, no `components.json` and no `@/` alias. There is also no formatter (Prettier) and no test runner.

The root `README.md` is the exercise brief, in Spanish. It is generated from the course lesson, so don't edit it by hand. `prompts.md` is a template that students fill in.

**Node.js 24+ is required.** The backend runs `.ts` files directly through `@poppinss/ts-exec`. Older Node versions fail with `ERR_UNKNOWN_FILE_EXTENSION ".ts"`.

## Commands

Backend (`cd backend`):

```bash
npm install && cp .env.example .env && node ace generate:key   # first-time setup
node ace migration:run          # apply migrations to tmp/db.sqlite3 and regenerate database/schema.ts
npm run dev                     # node ace serve --hmr  →  http://localhost:3333
npm test                        # all Japa suites: unit (tests/unit/**), functional (tests/functional/**)
node ace test functional        # a single suite
node ace test --files=functional/auth   # a single file (matched by path suffix; .spec.ts stripped)
node ace test --tests="signs up a user" # a single test, by title
npm run lint                    # eslint (@adonisjs/eslint-config)
npm run typecheck               # tsc --noEmit
npm run format                  # prettier (@adonisjs/prettier-config)
```

No tests exist yet. Only `tests/bootstrap.ts` is present, and the functional suite starts the HTTP server automatically. Tests use the same SQLite file as development (`tmp/db.sqlite3`); `.env.test` only switches the session driver to `memory`.

Frontend (`cd frontend`):

```bash
npm run dev      # vite  →  http://localhost:5173
npm run build    # tsc -b && vite build (the only type check)
npm run lint     # oxlint (.oxlintrc.json)
```

## Backend architecture

A request passes through these stages in order: `start/kernel.ts` middleware → `start/routes.ts` → controller → VineJS validator → Lucid model → transformer → `ctx.serialize()`.

- **Generated files: don't edit them.**
  - `.adonisjs/server/controllers.ts` is the controller index. Routes reference controllers as `controllers.X` from `#generated/controllers`, not through direct imports.
  - `.adonisjs/client/` is the Tuyau typed-client registry, exported as `backend/registry`. The frontend doesn't use it yet.
  - Both are regenerated by the `init` hooks in `adonisrc.ts` (`indexEntities`, `generateRegistry`) whenever the dev server or the build runs.
- **The model's columns live in `database/schema.ts`.** That file is auto-generated from the DB by `node ace migration:run`. Models extend the generated classes: `User` extends `UserSchema` and only adds behavior (the auth-finder mixin, the `accessTokens` provider and the computed `initials`). To change columns, write a new migration and run it. Never edit `schema.ts` or an existing migration.
- **Import aliases** such as `#models/user` and `#validators/user` come from Node subpath imports in `backend/package.json`, not from tsconfig paths.
- **Response envelope.** `providers/api_provider.ts` adds `ctx.serialize()`, which wraps payloads as `{ data: ... }`. Transformers (`app/transformers/`) decide which fields are exposed by picking them from the model. `logout` is the one exception: it returns a bare `{ message }`.
- **Errors are always JSON.** `force_json_response_middleware` overwrites `Accept`, so every error has the shape `{ errors: [{ message, rule?, field?, meta? }] }`.
- **Auth.** The default guard is `api`: opaque access tokens stored in `auth_access_tokens`. Token values carry the `oat_` prefix and are sent as `Authorization: Bearer <token>`. A `web` session guard is configured, but no route uses it. CSRF is disabled. CORS allows any origin in dev and none in production (`config/cors.ts`).

## API contract

These endpoints were verified against the running backend. All paths are under `/api/v1`.

| Endpoint | Auth | Request body | Success (200) |
|---|---|---|---|
| `POST /auth/signup` | none | `{ fullName, email, password, passwordConfirmation }` | `{ data: { user, token } }` |
| `POST /auth/login` | none | `{ email, password }` | `{ data: { user, token } }` |
| `GET /account/profile` | Bearer | none | `{ data: user }` |
| `POST /account/logout` | Bearer | none | `{ message }` (no `data` wrapper) |

Here `user` is `{ id, fullName, email, createdAt, updatedAt, initials }`.

The signup validator (`app/validators/user.ts`) enforces rules that a product ticket usually doesn't spell out:

- **`fullName` must always be sent.** `null` is accepted, but omitting the key returns 422 (`rule: "required"`).
- **`passwordConfirmation` is required** and must equal `password`.
- **`password`** must be 8–32 characters.
- **`email`** must be a valid email of at most 254 characters, and unique. A duplicate email returns 422 with `field: "email"` and `rule: "database.unique"`.

Other error statuses:

- 400 `Invalid user credentials` on a bad login.
- 401 `Unauthorized access` when the token is missing or invalid.

## Frontend notes

- There's no router, API client or state library yet. The entry point is `src/main.tsx` → `src/App.tsx`.
- `vite.config.ts` has no dev proxy. Call the backend at `http://localhost:3333` directly; CORS is open in dev.
- The tsconfig settings restrict module syntax:
  - `verbatimModuleSyntax`: use `import type` for type-only imports.
  - `erasableSyntaxOnly`: no `enum`, no `namespace`, no constructor parameter properties.
  - `noUnusedLocals` and `noUnusedParameters` are on, and `npm run build` fails on violations.
- Code style in both packages: single quotes and no semicolons. The backend enforces this through its Prettier config; the frontend follows it by convention only.

## Workflow rules

1. Before touching any code, create a new branch from the current one (`feat/<TICKET-KEY>-<short-slug>`).
2. When the work is done, commit with `/commit` and open the pull request with `gh pr create`.
3. Then run the `adversarial-reviewer` subagent on that pull request.
4. In the chat, reply only with the pull request URL.

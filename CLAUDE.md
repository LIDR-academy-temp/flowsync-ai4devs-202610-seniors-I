# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this repo is

FlowSync is a course exercise repo (LIDR Academy, AI4Devs). It's a TypeScript monorepo with two independent npm projects. There's no root `package.json`, so run commands inside each folder:

- `backend/`: AdonisJS 7 API (Lucid ORM on SQLite, VineJS validation, token auth). **It already exists and you shouldn't modify it during the exercise.** Read it to learn the API contract.
- `frontend/`: React 19 + Vite 8, currently the bare Vite template. This is where you build features (for example, the login/signup ticket). The course plans to use shadcn/ui components, which get copied into the repo rather than installed as a dependency. They aren't set up yet.

The root `README.md` is generated from the course lesson (don't edit it by hand). `prompts.md` is a template that students fill in with their prompts. Deliverables go in `docs/harness/comparacion.md` and `prompts.md`.

Node.js **24+** is required. On older versions the backend fails with `Unknown file extension ".ts"`.

## Commands

Backend (`cd backend`), served at http://localhost:3333:
```bash
npm install && cp .env.example .env && node ace generate:key   # first-time setup
node ace migration:run      # creates tmp/db.sqlite3 and regenerates database/schema.ts
npm run dev                 # node ace serve --hmr
npm run lint | npm run typecheck | npm run format
npm test                    # node ace test (Japa); suites: unit, functional
node ace test functional    # run one suite
node ace test --files tests/functional/auth.spec.ts   # run a single file
node ace test --tests "test title"                    # run a single test by title
node ace make:migration <name> | make:controller | make:validator   # scaffolding
```
`tests/` has only `bootstrap.ts` for now. Specs go under `tests/unit/**/*.spec.ts` or `tests/functional/**/*.spec.ts`, and the functional suite starts the HTTP server automatically.

Frontend (`cd frontend`), served at http://localhost:5173:
```bash
npm run dev
npm run build     # tsc -b && vite build (this is also the typecheck)
npm run lint      # oxlint (.oxlintrc.json)
```
The frontend has no test runner. Prettier is configured (`npm run format`, `npm run format:check`), and a Claude Code hook (`.claude/hooks/format-frontend.sh`) formats every file under `frontend/src/` after each edit.

## Backend architecture

Request flow: `start/routes.ts` → controller → VineJS validator → Lucid model → transformer → `ctx.serialize()`.

- **Routes** (`start/routes.ts`) reference controllers through the generated `#generated/controllers` map (`.adonisjs/server/controllers.ts`, auto-generated by the `indexEntities` hook in `adonisrc.ts`, so don't edit it). All API routes are under `/api/v1`:
  - `POST /api/v1/auth/signup` → `NewAccountController.store`
  - `POST /api/v1/auth/login` → `AccessTokensController.store`
  - `GET /api/v1/account/profile` and `POST /api/v1/account/logout` sit behind `middleware.auth()`
- **Validation contract** (`app/validators/user.ts`) is stricter than product tickets usually say:
  - Signup requires `email` (unique, ≤254 chars), `password` (8–32 chars) and `passwordConfirmation` (must match `password`). `fullName` is nullable.
  - Login takes `email` and `password`.
  - When validation fails, the API returns **422** with `{ errors: [{ field, message, rule }] }`. Bad credentials on login (`verifyCredentials`) return **400** with an `errors` array.
- **Response shape**: `providers/api_provider.ts` adds `ctx.serialize()`, which wraps payloads in `{ data: ... }`.
  - Signup and login return `{ data: { user, token } }`.
  - Profile returns `{ data: user }`.
  - `UserTransformer` controls the exposed user fields: `id, fullName, email, createdAt, updatedAt, initials`. It never exposes the password.
  - Logout returns a plain `{ message }`, without the wrapper.
- **Auth**: the default guard is `api`, an opaque access-token guard. Tokens start with `oat_` and are sent as `Authorization: Bearer <token>`. They're stored in `auth_access_tokens`. A session guard `web` exists but the routes don't use it.
- **Global middleware**: `force_json_response` makes every response JSON, including errors. In dev, CORS allows any origin with credentials. CSRF is disabled.
- **Database**: SQLite at `backend/tmp/db.sqlite3`. To change the schema, add a new migration; never edit existing ones or the table directly.
  - `database/schema.ts` is **generated** from the migrations when you run `migration:run`.
  - Models extend the generated schema classes, for example `User extends compose(UserSchema, withAuthFinder(hash))`.
- **Import aliases**: use the `#controllers/*`, `#models/*`, `#validators/*`, `#transformers/*` (and other) subpath imports from `backend/package.json`. They resolve to `.js` even though the sources are `.ts`.
- **Generated typed API client**: Tuyau's `generateRegistry` hook generates `.adonisjs/client/` (routes registry and types), exported as `backend/registry` and `backend/data`.
- **Code style**: Prettier uses `@adonisjs/prettier-config` and ESLint uses `@adonisjs/eslint-config`.

## Process rules

- **Create a new branch before touching any code.** Never work directly on `main`.
- **When the work is done, commit with `/commit`**, then open the pull request with `gh pr create`.
- **After the pull request is open, run the `adversarial-reviewer` subagent on it.**
- **In the chat, reply with only the pull request URL.**

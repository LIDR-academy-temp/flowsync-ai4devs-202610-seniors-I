## What this repo is

FlowSync is a course exercise (AI4Devs, module 1) with two independent apps in one repo, TypeScript end to end:

- `backend/` — AdonisJS 7 API (Lucid ORM on SQLite, VineJS validators, token auth). **Already complete; treat it as read-only** unless explicitly asked to change it. Read it to learn the real API contract.
- `frontend/` — React 19 + Vite 8, still the bare Vite template (no router, no UI library, no formatter, no tests yet). This is where feature work happens. The course expects shadcn/ui for components.

`README.md` is generated from the course lesson (do not edit by hand). Docs and deliverables are in Spanish; exercise deliverables are `prompts.md` (root) and `docs/harness/comparacion.md`.

## Commands

Requires **Node.js 24+** (older versions fail with `Unknown file extension ".ts"`).

Backend (run from `backend/`):

```bash
npm install && cp .env.example .env && node ace generate:key && node ace migration:run   # first-time setup
npm run dev          # node ace serve --hmr, http://localhost:3333
npm run lint         # eslint (@adonisjs/eslint-config)
npm run typecheck    # tsc --noEmit
npm run format       # prettier (@adonisjs/prettier-config)
npm test             # node ace test (Japa); suites: unit (tests/unit), functional (tests/functional)
node ace test functional                          # one suite
node ace test --files=tests/functional/auth.spec.ts   # one file
node ace test --tests="test title"                # one test by title
```

No test files exist yet; only `tests/bootstrap.ts` (functional suite boots the HTTP server; `apiClient` + `authApiClient` plugins are registered). `.env.test` uses `SESSION_DRIVER=memory`.

Frontend (run from `frontend/`):

```bash
npm install
npm run dev      # http://localhost:5173
npm run build    # tsc -b && vite build (this is the typecheck)
npm run lint     # oxlint
```

## Backend architecture (the API contract the frontend consumes)

Routes in `backend/start/routes.ts`, all under `/api/v1`:

| Route                  | Auth         | Body                                                                        |
| ---------------------- | ------------ | --------------------------------------------------------------------------- |
| `POST /auth/signup`    | –            | `email`, `password`, `passwordConfirmation`, `fullName` (optional/nullable) |
| `POST /auth/login`     | –            | `email`, `password`                                                         |
| `GET /account/profile` | Bearer token | –                                                                           |
| `POST /account/logout` | Bearer token | – (deletes current token)                                                   |

Things that require reading several files to see:

- **Validation rules live in `app/validators/user.ts`**, not in route or controller: email ≤254 chars; signup password 8–32 chars and `passwordConfirmation` must match; email must be unique in `users`. Failed validation returns HTTP 422 with an `errors` array (field + message).
- **Response envelope**: `providers/api_provider.ts` adds `ctx.serialize()`, which wraps payloads in `{ data: ... }`. Signup and login both return `{ data: { user, token } }`; profile returns `{ data: user }`. The user shape is defined by `app/transformers/user_transformer.ts` (`id, fullName, email, createdAt, updatedAt, initials`).
- **Auth**: default guard is `api` (access tokens, `config/auth.ts`). Tokens are prefixed `oat_` and sent as `Authorization: Bearer <token>`. Bad login credentials come from `User.verifyCredentials` (the `withAuthFinder` mixin), not from a hand-written check.
- `force_json_response_middleware` forces JSON responses for every request, including errors.
- CORS allows every origin in dev (`config/cors.ts`), so the frontend can call `http://localhost:3333` directly; there is no Vite proxy configured.
- Imports use Node subpath aliases (`#models/*`, `#validators/*`, `#controllers/*`, … in `backend/package.json`).

Generated files — never edit by hand:

- `backend/.adonisjs/**` (controller index used by `routes.ts` as `controllers.X`, and the Tuyau client registry) — regenerated by the assembler hooks in `adonisrc.ts` when running `dev`/`build`.
- `backend/database/schema.ts` — regenerated by `node ace migration:run`. Models extend these classes (e.g. `User extends compose(UserSchema, withAuthFinder(hash))`), so schema changes go through a **new migration**, never by editing tables or `schema.ts`.

## Frontend notes

- TS config (`tsconfig.app.json`) is strict about unused locals/params and uses `verbatimModuleSyntax` (use `import type` for type-only imports) and `erasableSyntaxOnly` (no enums/namespaces/parameter properties).
- Oxlint enforces `react/rules-of-hooks` and warns on `react/only-export-components`.

## Process rules

1. Before editing any file, create a branch (e.g. `feat/FLOW-3-login`). Never work directly on the current branch.
2. When done, commit using the `/commit` skill and open the pull request with `gh pr create`.
3. Then run the `adversarial-reviewer` subagent on that PR and post its full report as a PR comment (`gh pr comment <number> --body-file <file>`).
4. The final message is just the PR link.

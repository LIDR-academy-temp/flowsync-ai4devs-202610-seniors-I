# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this repo is

FlowSync is a course exercise repo (LIDR AI4Devs): a TypeScript monorepo with two independent npm projects, `backend/` (AdonisJS 7 API) and `frontend/` (React 19 + Vite). There is no root `package.json`; run every command from inside the relevant subfolder. The README (in Spanish) is generated course material and must not be edited by hand. `prompts.md` is where the student logs, verbatim, every prompt they launched.

**The backend already exists and is not meant to be modified for the current exercise**; work happens in `frontend/`. Read the backend to learn the API contract, especially the validators, which specify more than a product ticket usually does.

Requires Node.js 24+ (older versions fail with `Unknown file extension ".ts"`).

## Commands

Backend (`cd backend`), served at http://localhost:3333:

```bash
npm install
cp .env.example .env && node ace generate:key   # first time only
node ace migration:run                           # SQLite at backend/tmp/db.sqlite3; also regenerates database/schema.ts
npm run dev                                      # node ace serve --hmr
npm run lint | npm run typecheck | npm run format
npm test                                         # node ace test (Japa)
node ace test functional                         # one suite (unit | functional)
node ace test --files=tests/functional/auth.spec.ts   # one file
node ace test --tests="signs up a user"          # one test by title
```

Test suites are declared in `adonisrc.ts` (`tests/unit/**/*.spec.ts`, `tests/functional/**/*.spec.ts`); no spec files exist yet. Functional suites start the HTTP server automatically (`tests/bootstrap.ts`), and `.env.test` uses the in-memory session driver.

Frontend (`cd frontend`), served at http://localhost:5173:

```bash
npm install
npm run dev
npm run build    # tsc -b && vite build (this is also the typecheck)
npm run lint     # oxlint
npm run format   # prettier --write src (format:check to verify only)
```

The frontend has no test runner yet.

## Backend architecture (AdonisJS 7)

- **Routes** (`start/routes.ts`), all under `/api/v1`:
  - `POST /auth/signup` → `NewAccountController.store`
  - `POST /auth/login` → `AccessTokensController.store`
  - `GET /account/profile` → `ProfileController.show` (auth required)
  - `POST /account/logout` → `AccessTokensController.destroy` (auth required)
- Controllers are referenced through the generated `controllers` map from `#generated/controllers`; imports use the `#alias/*` subpath imports defined in `backend/package.json`.
- **Auth**: the default guard is `api` (opaque access tokens stored in DB, values prefixed `oat_`). Clients send `Authorization: Bearer <token>`. A `web` session guard is configured but not used by the routes.
- **Validators** (`app/validators/user.ts`, VineJS) are the source of truth for request bodies. Signup requires `email` (unique), `password` (8–32 chars) **and `passwordConfirmation`** (must match), with `fullName` optional/nullable. Login takes `email` + `password`. A frontend that sends only email+password to signup will get a 422.
- **Responses** go through `ctx.serialize(...)` (custom serializer in `providers/api_provider.ts`), which wraps payloads in `{ "data": ... }`. Signup and login return `{ data: { user, token } }`; profile returns `{ data: user }`. What a user exposes is defined by `app/transformers/user_transformer.ts` (`id, fullName, email, createdAt, updatedAt, initials`).
- `ForceJsonResponseMiddleware` makes every response JSON, including errors (validation errors come back as `{ errors: [{ field, message, rule }] }`).
- CORS allows any origin in development (`config/cors.ts`), so the frontend can call `http://localhost:3333` directly; Vite has no proxy configured.
- **Models** extend generated schema classes: `User` extends `UserSchema` from `database/schema.ts`. Schema changes go in a new migration under `database/migrations/`, then `node ace migration:run`.

### Generated files: do not edit by hand

- `backend/database/schema.ts`: regenerated by `node ace migration:run`.
- `backend/.adonisjs/`: controller index and the Tuyau client registry, regenerated by the dev server/build hooks in `adonisrc.ts`. The registry is exported as `backend/registry` and `backend/data` and is typed into the Japa API client.

## Frontend

A stock Vite + React 19 template (`src/App.tsx` is still the starter page), with no router, no UI library and no API client yet. The course expects shadcn/ui for components (copied into the repo, not installed as a dependency).

Prettier (`frontend/.prettierrc.json`) runs automatically on every edited file under `frontend/src/` via a PostToolUse hook (`.claude/hooks/format-frontend.sh`); `npm run format` formats everything by hand.

## Process rules

Follow these steps, in order, for every task in this project:

1. **New branch before touching code.** Before the first edit, create a branch from the current one: `git checkout -b <type>/<JIRA-KEY>-<short-slug>` (e.g. `feat/FLOW-5-frontend-login`; without a ticket, drop the key). Note the branch you started from: it is the PR base.
2. **Close the iteration with `/commit` and a PR.** When the iteration is implemented, stage the changes for the task (only those) and run the `/commit` skill. Then push: `git push -u origin <branch>`.

   **Before creating the PR, ask the user which repo it goes to** (use `AskUserQuestion`; never pick one yourself):
   - Original course repo: `LIDR-academy-temp/flowsync-ai4devs-202610-seniors-I` (upstream)
   - The user's fork: `LluisArevalo/flowsync-ai4devs-202610-seniors-I` (origin)

   Then always create it with an explicit `--repo` matching the answer, and confirm with the user if the base branch does not exist in that repo:

   ```bash
   # Original repo: the head lives in the fork, so prefix it with the fork owner
   gh pr create --repo LIDR-academy-temp/flowsync-ai4devs-202610-seniors-I --base <starting-branch> --head LluisArevalo:<branch> --title "<conventional commit subject>" --body "<summary + Refs: JIRA-KEY>"
   # Fork
   gh pr create --repo LluisArevalo/flowsync-ai4devs-202610-seniors-I --base <starting-branch> --head <branch> --title "…" --body "…"
   ```

3. **Review the PR with the reviewer subagent.** Once the PR exists, launch the `adversarial-reviewer` subagent, passing it the full PR URL (not just the number, so it reviews the PR in the repo where it was created).
4. **Return the PR URL in the chat.** Finish by replying with the PR URL.
